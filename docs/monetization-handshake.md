# skill-picker 变现与握手：已锁定的设计决定

本文记录**已经定下、后续实现必须遵守**的决定，以及每条决定的理由和被否掉的
替代方案。凡是标「未锁定」的，实现时必须回来确认，不要自行选一个往下做。

前提事实（都经过查证，不是判断）：

- `LICENSE` 是 MIT，代码已在 GitHub 公开，任何人可永久 fork 当前版本。
- 全仓库 12 个 commit **只有一个作者**，所以改授权无需征求他人同意——但只能
  约束未来版本，已发布的那份追不回。
- 纯 Python 源码、零第三方依赖、找/理 100% 本地。
- 全仓库**没有任何**授权、订阅、激活、用量限制、支付相关代码或文档。
- 全仓库**没有任何**遥测：没有 match 次数、看板打开次数、skill 选用结果的落盘，
  只有 TTL 300 秒的 `pending_intent.json`。也就是说当前**无法度量任何东西**。
- `install` 只安装 picker 自身（meta-skill 进四宿主 + MCP 注册三处 + Cursor
  全局规则），**没有安装第三方 skill 的能力**。

---

## D1（已锁定）付费边界：本地能算出来的免费，需要服务端才知道的付费

SKU 是 **skill-picker Pro**，采用开源核心：免费层保持 MIT 开源，付费层单独闭源。

### 免费层（开源，永久）

`scan` / `match` / `dashboard` / 五道门禁 / 重复与漂移检测 / MCP / 发现 tab，
**以及一键安装、装完体检、回滚**（`add` / `installed` / `remove`，已落地）。

免费层必须保持匿名、本地、不要求登录。它是分发引擎——`install` 会往四个宿主
写 meta-skill 并注册 MCP，是每天都会被触发的触点。在漏斗入口收费等于自断增长。

### 付费层（Pro，闭源 + 服务端锚定）

- **上游新鲜度**：你装的 skill 里哪些上游有更新、哪些作者已弃坑、哪些被更好的
  替代了。
- **精选包与推荐**：选品劳动的产物。
- **团队共享 catalog 与 skill 对齐**：新人入职一键装齐团队标准技能栈，跨成员
  漂移检测。
- **私有 skill 源**：接入企业内部 git 仓库。

### 为什么这样划（这是本文最重要的一条）

纯本地的 Python 源码上做授权校验是纸糊的，删几行就绕过。所以付费能力必须
**锚定在服务端**——上述四项的共同点是「本地算不出来」：本机看不到上游仓库的
最新状态，看不到别人的 catalog，看不到我们的选品结果。

由此得到一个反直觉但必须坚持的结论：**一键安装要放在免费层**。它是纯本地代码，
几分钟就能破解，把它设为付费卖点买不到任何保护；而它同时是增长引擎，也是
`installed` 这个真信号的唯一来源。

不做 DRM。让服务端成为必需品，那么破解客户端拿到的是个空壳。

**被否掉的替代方案**：把一键安装设为 Pro 卖点。理由如上——收不到钱，还要牺牲
漏斗和度量能力。

## D2（已锁定）在网页买，在 picker 激活

picker 是本地 CLI，收款必须在 web：微信支付需要企业资质与类目审核，依赖正在
办的 ICP 备案与公众号认证。所以购买发生在 `skillfeeder.cn`，权益送达 picker。

**第一版权益送达用激活码粘贴**，不依赖浏览器到 localhost 的通道（理由见 D3
流 4）。权益文件落在 `~/.skill-picker/`，绑设备。

**未锁定**：具体的权益文件格式、绑几台设备、换机怎么迁。等第一个 SKU 定价定了
再定，因为「绑几台」是定价的一部分。

## D3（已锁定）握手分四条流，机制各不相同

关键事实：`discover.py` 会把 skill-feed 的 lite 页**拷成本地文件**
`~/.skill-picker/discover.html`。当它存在时（`DISCOVER_READY`），dashboard 里那个
iframe 加载的是**同源**文件，不是跨域。

### 流 1：picker 内发起安装 —— 同源直连，零协议

主路径。因为同源，picker 的看板可以直接驱动内嵌的 feed 页面，不需要任何网络
协议、不受 CORS 与混合内容限制。卡片上的「装到本机」走这条。

### 流 2：站内发起装到本机 —— 只做命令兜底

用户在普通浏览器逛 `skillfeeder.cn` 时想装到本机，必须跨 https → localhost。
两道坎：`serve` 目前**只有 `do_GET`、没有 `do_POST`、完全没有 CORS 头**；以及
Chrome 的 Private Network Access 对公网页面请求本地地址有预检要求。

**第一版只做兜底**：站上给一行可复制的命令。零浏览器限制，永远可用。

**未锁定**：要不要做 fetch 到 localhost 的体验版。做之前**必须在 Chrome 和 Edge
上实测**现代浏览器对 https → `127.0.0.1` 的实际行为，不许按假设实现。自定义
协议 `skillpick://` 也是候选，但要注册系统 handler，会抬高装机复杂度。

### 流 3：installed 回传 —— 走 picker 自己的出网，不经浏览器

价值最高、成本最低，且**先做这条**。

它替掉现在那个只能证明「点了链接」的 `opened_github`。双向价值：feed 拿到真实
转化信号（三条排序规则里的规则一依赖「本站点击最多」，这个信号才算立起来）；
feed 可以标记用户已装的条目，并提示「这个和你已装的 X 重复」——picker 本来就在
算重复和漂移，这部分几乎免费。

对用户的价值是这条得以成立的前提，见 D4。

#### 流 3 拆两半，第一半已落地（零出网）

这条流里「feed 标记用户已装的条目」和「回传给 feed 服务端」是可以分开的，前者
不需要任何服务端。已实现的部分：

`discover.py` 在同步 lite 页时，把本机 catalog 压成一个只含 `{名字: {份数,
宿主, 是否漂移}}` 的索引，作为 `application/json` 数据块注进
`~/.skill-picker/discover.html`。feed 页面读这个块，在命中的卡片上挂一枚角标；
漂移的显红。整条链路在本地文件之间完成，不发一个请求，也不写任何东西回 feed。

三条刻意的约束：

- **只报"同名"，不报"已安装"**。本机 catalog 没有 GitHub 坐标（详见下方"未锁定"），
  唯一可用的连接键是 skill 名与 `skill_path` 末级目录名，同名不同仓会误命中。
  所以文案是「本机已有同名」而不是「已安装」。
- **索引里没有任何绝对路径**，只有名字、份数、宿主名、漂移布尔值。
- **漂移状态直接复用 `catalog["duplicates"]`**，不在注入侧重算，避免两套判定漂移。

公开站点（`skillfeeder.cn`）不存在这个数据块，读取代码静默降级，卡片与现在完全
一致。CSP 不受影响：`application/json` 不是可执行脚本，`script-src` 仍然只认那
一个内联块的哈希。

#### 第二半的收数端：先 GitHub Issue，规模上来再迁无服务器函数（已锁定）

feed 是 GitHub Pages 纯静态产物，没有后端，所以回传必须先决定收在哪。

**第一版写 GitHub Issue**。理由不是它优雅，是它在当前阶段唯一不引入新麻烦：零
运维、零成本、复用已有的 GitHub 凭据，而且数据落在公开仓库里——这一点意外地
重要，因为它让「无服务器、无账号」这句宣传语依然成立，不需要为一条遥测去备案
一个新域名、写一份隐私政策。审计成本也归零：用户想知道自己上报了什么，点开
Issue 就看得到。

代价要认：粒度粗（一条 Issue 一批聚合，不是逐事件）、有被灌水的风险（必须限
频，并且**只在用户显式同意后**才写），以及 Issue 列表会变脏（用固定 label 隔
离，或专开一个 `*-telemetry` 仓）。

**规模上来再迁无服务器函数**（Vercel / Cloudflare Workers 免费额度足够）。迁移
的触发条件是这两件之一：需要按事件粒度而不是批次聚合；或者限频挡不住滥用。迁
的时候域名要连带处理备案与隐私声明——这就是第一版不选它的原因。

**自建被否**：要机器、要备案、要一份运维手册，而它换来的灵活度当前用不上。

**顺带记一笔**：把本机 catalog 补上来源仓库坐标（安装时存证），能让上面那个
连接键从"同名猜测"变成精确匹配。它属于实现顺序第 2 项（一键安装 + 来源存证）
的副产品，届时这枚角标的文案可以从「同名」升级成「已安装」。

**已解锁**：第 2 项做完后 `~/.skill-picker/installed.json` 里有了 `owner/repo` +
`subdir`，凡是经 `add` 装的条目都能和 feed 精确对上。角标升级的做法是让
`discover.py` 注入的索引多带一个精确层：存证命中 → 文案「已安装」，仅名字命中 →
仍是「本机已有同名」。两层要分开，别把猜测混进确证里。

### 流 4：权益送达 —— 激活码粘贴

见 D2。不依赖流 2，避免把收款成功率押在浏览器的本地网络策略上。

## D4（已锁定）遥测：默认关闭、显式征询、必须回报

当前宣传语原文是「**100% 本地｜无服务器、无账号、无外部 API、零第三方依赖**」。
加遥测直接和它冲突，所以：

1. **默认关闭**，首次可能上报前显式征询。
2. **必须回报**——上报换来用户看得见的东西（例如「你装的 3 个 skill 有新版」）。
   单向索取的遥测不做。
3. **最小集**：只报聚合与必要字段，不报单用户轨迹。
4. **把宣传语改准确**。这句话**现在就已经不准确**了：发现 tab 在本地未同步时会
   iframe 加载 `469910093-ui.github.io` 的远程 embed，而 `dashboard.py` 文件头
   还写着「无外部资源」。开源项目里这是小瑕疵，**一旦收钱就是虚假宣传**，而且
   正在走备案与公众号审核。

**被否掉的替代方案**：静默加遥测。对一个以「无服务器无账号」为卖点、且拥有用户
开发环境写权限的工具，这是最坏选项。

**征询文案必须写明数据是公开的**。第一版收数端是公开仓库的 GitHub Issue（见 D3
流 3），这跟"上报到我们的服务器"是两种不同的隐私承诺，不能含糊过去。反过来
说，这也是最容易解释清楚的一种：上报了什么，用户点开 Issue 自己就能核。

## D5（已锁定）代装第三方 skill 会改变安全责任的性质

现在 picker **只读**，多处代码声明永不修改用户已有 skill。一旦它开始把第三方
`SKILL.md` 写进用户的 agent 宿主目录，它就成为**供应链攻击面**：`SKILL.md` 是
给 agent 读的指令，恶意内容可以指使用户的 agent 做任何事（读密钥、执行命令）。

**收费会放大这个责任**：免费是「你自己去 GitHub 装的」，收费是「我卖给你的包」，
等于隐含担保了安全性。

这不是理论风险。skill-feed 侧刚修完一个存储型 XSS，来源正是不可信的 SKILL.md
内容——同一个数据源，只是代价从「站上执行 JS」升级为「用户开发机上执行任意操作」。

因此一键安装必须同时具备（**引擎层已全部落地**，见下）：

| 要求 | 落地情况 |
|---|---|
| 装前展示来源仓库、star、以及将写入的目标路径 | `add` 不带 `--yes` 只出计划：来源、子目录、ref、commit、目标路径、文件清单、冲突。star 暂缺（CLI 侧不打 API，卡片按钮那条流会带上） |
| **同名冲突绝不覆盖**（守住只读铁律，只能改名／跳过／询问） | 目标目录存在即硬阻塞，**没有 `--force` 覆盖开关**；出路只有 `--as` 改名或先 `remove` |
| 来源存证：包 ID、版本、源 URL、sha256（这同时就是购买凭证） | `~/.skill-picker/installed.json`：`host:dir` 作 ID，源 URL / ref / commit / 逐文件 sha256 |
| 装完自动跑 `scan` + 五道门禁 | 先逐文件比哈希（不一致自动回滚），再重扫 + 确认进 catalog + 跑门禁 |
| 可卸载、可回滚 | `remove` 只删存证里自己写过、且装完没被改动过的文件；改动过的默认拒删，用户新增的文件一律保留 |

解包按不可信输入处理：跳目录、绝对路径、符号链接、大小写撞名、Windows 保留名、
体积与文件数上限全部在门口拒掉。30 个变异全部被测试抛住。

**未锁定**：Pro 精选包要不要人工安全审核、审核到什么深度。这条直接决定担保责任
的大小，定价前必须回答。

## D6（已锁定）供给端质量信号是变现的前置条件，不是后续优化

实测数据：本机语料 4175 条里只有 **32 条**是真 skill；当前 feed 中 388 条有
**93.6% 是 monorepo 子条目**，共享母仓库星数，star 本身没有区分度。

结论：**当前没有可靠的质量信号来选品**。一键安装做完之后，「包里装什么」仍然是
个开放问题。如果精选包是从质量未验证的池子里挑 12 个，会退货、不会复购。

已经建起来的**飞书译稿审校流水线 + 双语人话层**是真正的护城河——那是选品劳动的
沉淀，fork 不走。MIT 意味着别人可以 fork 客户端指向自己的源，防线从来不是代码，
而是内容、渠道（小红书／抖音／公众号）和已安装用户的习惯。

所以钱和工时该花在选品与内容上，不是花在授权校验上。

## 实现顺序（已锁定）

1. 流 3 `installed` 回传 + 遥测征询（D3／D4）——点亮漏斗，否则定价和打包全靠猜
   - 本地一半（feed 标记本机同名条目）**已完成**，零出网
   - 回传一半待选址，见 D3 流 3
2. 一键安装 + 装完体检 + 回滚，放在**免费层**（D1／D5）——CLI 引擎层
   （`add` / `installed` / `remove`）**已完成**，见 D5 落地表
3. 流 1 卡片「装到本机」（D3）
4. 供给端质量信号（D6）
5. 第一个 Pro 能力与激活链路（D1／D2）

先做度量、再做能力、最后做收费。理由：现在 feed → GitHub → 装上这条漏斗完全
是黑的，在未度量的漏斗上建收费墙，等于蒙着眼睛定价。
